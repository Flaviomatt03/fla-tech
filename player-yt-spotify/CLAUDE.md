# Duetto – note per Claude

PWA per iPhone (uso personale) con playlist ibride Spotify + YouTube. Interfaccia e testi in **italiano**.

- App statica in `web/` (HTML/CSS/JS moduli ES, **nessuna build, nessuna dipendenza**). Hosting: **Vercel** (`vercel.json`, output `web`, nessuna build), deploy automatico da `main`. Netlify (`netlify.toml`) abbandonato: crediti gratuiti esauriti, deploy in pausa. Raggruppare le modifiche: meno rilasci possibili.
- Il lavoro va pushato su `main` (richiesta dell'utente: ogni chat deve partire allineata).
- Spotify: OAuth PKCE + Web API; riproduzione via Spotify Connect (`/me/player/*`). Regole Development Mode feb. 2026: search `limit` max 10, `/playlists/{id}/items` (campo `item`), niente endpoint batch.
- YouTube: Data API v3 per ricerca/import. **Riproduzione solo da locale** (scelta dell'utente, nov. 2026): YouTube blocca come "bot" tutti i server pubblici (Piped/Invidious) e il lettore ufficiale non suona a schermo spento. I brani si scaricano sul telefono con il comando rapido iOS **"Scarica per Duetto"** (a-Shell + yt-dlp; Duetto lo apre con `shortcuts://run-shortcut?...` da "Scarica sul telefono" / "Scarica i brani YouTube"; guida in Impostazioni → YouTube; tutti i file in un'unica cartella `~/Documents/Duetto` = File → a-Shell → Duetto, perché un file può stare in più playlist) e si importano da **Aggiungi → File**: i file sostituiscono il brano YouTube al suo posto, riconosciuti dal codice del video nel nome del file (`[id]`, template yt-dlp `%(title)s [%(id)s].%(ext)s`) o dal titolo (`titleKey`) (`store.replaceTrack`). File = brani `source: 'file'` salvati in IndexedDB (store `audio`, chiave `file:<id>`, `saveFile` in `ytaudio.js`), suonati da `<audio>` (`audioId()`), salvati come **copia vera dei byte** (`new Blob([await file.arrayBuffer()])`, poi riletti e verificati: un File di iOS salvato così com'è può restare un riferimento a un file temporaneo che iOS cancella → "WebKitBlobResource error"); niente doppioni (`findSameFile`: stesso nome e dimensione); un file sostituisce il brano YouTube con lo stesso titolo in **tutte** le playlist; righe "File mancante" se la copia non c'è (`fileExists`, indice letto all'avvio): reimportando un file con stesso nome o titolo (`findMissingFile`) o toccando la riga (`linkFileSheet`) la copia si ricrea con lo STESSO id e tutte le playlist tornano a posto; i file non si cancellano mai da soli (scelta dell'utente: `gcFiles` non viene più chiamato), solo a mano da Impostazioni. Un brano YouTube non scaricato viene saltato con avviso "Scarica" (evento `missing`); in lista appare attenuato "Da scaricare". Al ritorno dal comando rapido: per una singola canzone si apre il foglio "Collega il file" (`linkFileSheet`) che associa il file scelto a quella canzone in tutte le playlist (`linkFileToTrack`); per più canzoni si apre Aggiungi → File. Righe "Da scaricare": pulsante ↓ e il tocco avvia lo scaricamento; menu brano "Collega un file". Schermo spento: unico `<audio>` persistente + Media Session, prossimo brano pronto in memoria (`localUrls`), `holdSession` (silenzio) solo per tenere viva l'app durante i passaggi. Con Spotify in riproduzione la Media Session di Duetto viene svuotata, così l'iPhone mostra Spotify. Il vecchio codice Piped/IFrame resta ma non è usato.
- UI nativa iOS secondo le Human Interface Guidelines: font di sistema SF con Dynamic Type (`font: -apple-system-body`, misure in rem), colori di sistema chiaro/scuro, Liquid Glass su barre/fogli, barra schede con etichette, titoli grandi che si riducono, scorrimento dal bordo per tornare, scorrimento sulle righe, fogli di azioni con Annulla separato. Un solo accento: ambra (`--accent`/`--accent-fill`). Fonte del brano = puntino verde (Spotify) / rosso (YouTube) / ambra (file); un file nato su YouTube (non da una copia di Spotify: `fromYouTube` in ui.js; flag `yt` messo da `store.replaceTrack` quando un file sostituisce un brano YouTube, e da `enrichFiles` su tutti i file fuori dalle copie senza origine Spotify, perché i file arrivano solo da YouTube) ha ambra + rosso; un file scaricato per un brano Spotify (copia su YouTube, `origin` = `spotify:…`: `fromSpotify`) ha ambra + verde; secondo puntino da `fileOrigin`, in lista (`dots`), nel mini player e nel player grande (`#mini-dot2`, `#fp-dot2`). Niente font personalizzati.
- Nome **Duetto**, icona in `web/icons/icon.svg` (tre barre verde/ambra/rossa); le PNG si rigenerano da lì.
- Sync Spotify a senso unico (`sync.js`, `mergeSync` in `util.js`): le playlist Spotify diventano playlist della libreria; i brani aggiunti a mano restano. "Ripristina playlist Spotify" (Impostazioni, e una volta sola in automatico in v29) = `syncSpotify({ full: true })`: ignora gli snapshot, svuota le nascoste, fonde le copie con lo stesso `spotify.id` (`prepareFullSync`); rinomine, brani a mano e rimossi restano.
- Playlist salvate in **IndexedDB** (`idbGet`/`idbSet` in `storage.js`, `ready` in `store.js`, migrazione automatica da localStorage): localStorage (~5 MB su iPhone) si riempiva con librerie grandi e i salvataggi fallivano in silenzio. In localStorage solo dati piccoli (impostazioni, token, finestra della coda in `hp.player`). Lettura con 3 tentativi; copia di sicurezza `hp.playlists.bak` in IndexedDB ogni 6 h (usata se la principale manca); se la libreria non si legge → `isReadOnly()`: niente scritture né sync (altrimenti il sync ricreerebbe le playlist da zero). Ripristino backup: sostituisce per id o playlist Spotify, mai doppioni (`dedupe` toglie le copie "Nome (2)" identiche, anche all'avvio). Playlist nascoste (`hp.sync.ignored`) salvate sia in localStorage sia in IndexedDB.
- Spotify affidabile (`spotify.js`): `api()` ritenta 5xx/429/rete e rinnova il token; `play()` comanda **prima il dispositivo attivo** (poi quello salvato, poi il telefono) e manda `PUT /me/player/play` con contesto (vedi sotto; **mai** trasferire la riproduzione prima: su iPhone fa ripartire la canzone aperta in Spotify e il comando va perso); su 404/5xx attende e ritenta. `toggle()` riprende solo se Spotify ha in mano il nostro brano, altrimenti manda il brano. Diagnostica (`logEvent`/`getLog`, anche per YouTube: sorgente, pause di iOS, schermo spento/acceso) in Impostazioni → Assistenza; il nome del dispositivo è mostrato nel player (`#fp-device`); se l'elenco dispositivi è vuoto prova subito il telefono conosciuto, poi aspetta fino a 8 s che ricompaia; senza dispositivo lancia `NO_ACTIVE_DEVICE` → `player.needsDevice`, avviso "Apri Spotify" e nuovo tentativo al ritorno (`visibilitychange`). Spotify shuffle/repeat forzati a off. Alla conferma Spotify può dire "in pausa" mentre carica: si resta su "suona"; play con Spotify che suona già il nostro brano non manda comandi; brano equivalente = originale (`linked_from`, con `market=from_token` in `GET /me/player`; oppure `sameSong`: stesso titolo normalizzato e durata entro 5 s); lo sblocco audio al primo tocco è muto (un audio vero interrompe Spotify); "Spotify si è messo in pausa da solo" nella diagnostica. Il player **verifica** col polling che Spotify suoni davvero il brano chiesto (`CONFIRM_MS`): se no riprova (`commandLost`), poi "Spotify non risponde" + Apri Spotify.
- Fondo dello schermo (app installata su iPhone): difetto di **iOS 26** (WebKit bug 301108): con `black-translucent` + `viewport-fit=cover` la finestra dell'app installata è più corta dello schermo dell'altezza della barra di stato (iPhone 16e: 797 invece di 844) e sotto iOS **non disegna niente**: niente CSS/JS lo allunga (provato: spostare le barre sotto la finestra le taglia, v49). `fixViewport` misura `screen` − `innerHeight` in `--vp-gap`, che toglie lo spazio della barretta Home ormai inutile (`--safe-b` = max(0, inset − gap)), così barre e player arrivano al fondo della finestra; riga «schermo: … mancano N px» nella diagnostica; `settleViewport` fa `scrollTo(0,0)` dopo la tastiera. Alternativa non adottata: barra di stato opaca (`default`/`black`), richiede di rimettere l'app sulla schermata Home. **Attenzione:** su iPhone l'app installata ha dati suoi (separati da Safari) che si cancellano togliendo l'icona: playlist (tornano col backup), file audio, accesso Spotify, chiavi API e impostazioni. I file restano in File → a-Shell → Duetto e si reimportano in blocco. Barra delle schede ~28 pt dal fondo (`--tab-b`), mini player sopra (`--dock`).
- Titoli lunghi a scorrimento (`marquee` in ui.js, classe `.marq`, avanti e indietro con pause, ricalcolo con ResizeObserver, fermo con «riduci movimento»): player grande (titolo, artista), mini player (titolo), intestazioni dei fogli.
- Gesti: `trackSwipe` (ui.js) su mini player e copertina: precedente a sinistra, successivo a destra (`player.previousTrack`/`next`). Barra del minutaggio custom trascinabile (`initScrubber` in nowplaying.js, ruolo slider, frecce ±5 s).
- **Avvio dei brani Spotify con contesto** (verificato dalla diagnostica reale dell'utente e da una segnalazione di ott. 2026): su iPhone `PUT /me/player/play` con `uris` risponde 204 ma l'app riprende la canzone che aveva, anche con un solo brano. Si usa sempre `context_uri` + `offset.uri`: la playlist Spotify sincronizzata (`player.context.spotifyUri`, brani `synced`, niente casuale) oppure l'album del brano (`albumId`, o `GET /tracks/{id}` se manca). `makeRun` copre i brani consecutivi della playlist, o un solo brano in modalità album. Se il comando non viene eseguito: da playlist → riprova da album → "Spotify non risponde".
- Stato del player salvato in `hp.player` e ripristinato all'avvio (`player.restore`: si riaggancia a Spotify se suona ancora il blocco, altrimenti resta in pausa). `onAuthChange` notifica solo i cambi collegato/scollegato; durante il sync non si ridisegna.
- Coda come Spotify: `enqueue` inserisce dopo l'attuale e dopo gli altri brani `queued` (in ordine di aggiunta), `playNext` dopo l'attuale e dopo gli altri `playNext` (ordine di scelta), davanti agli `enqueue`; lo scorrimento sulla riga = `enqueue` (come Spotify: il primo aggiunto suona per primo); entrambi accorciano il blocco Spotify (`truncateRun`). Sezioni "In coda" / "Successivi" nel foglio Coda. A fine blocco Spotify si passa al brano successivo `EARLY_SWITCH_MS` (1,2 s) prima della fine, per non far sentire il brano successivo di Spotify. Widget di Spotify: iOS mostra il widget dell'app che suona, quindi con Spotify in riproduzione i comandi del widget vanno a Spotify (Duetto è sospeso). Al ritorno `handleSpotifyState` riallinea: Spotify su un brano precedente o sul successivo della coda → si aggancia (`findInQueue`); su un brano estraneo (avanti dal widget) → successivo di Duetto (`endRun`), anche dopo un riavvio dell'app se Spotify suona. Schermata di blocco: `nexttrack`/`previoustrack` registrati a ogni brano e `seekbackward`/`seekforward` a null (altrimenti iOS mostra ±10 s).
- **Copia su YouTube** (menu playlist, `cloneToYouTube`/`runClone` in app.js): playlist parallela "Nome (YouTube)" con `clone: { from, missing, missingKeys }`. Ogni brano della copia ha `origin` = `source:sourceId` del brano dell'originale da cui viene, e lo conserva quando diventa file (`store.replaceTrack` lo copia dal brano sostituito): è il legame che evita doppioni. "Aggiorna" (barra in cima alla copia con il numero di differenze, e menu "Aggiorna dalla playlist Spotify") = `cloneDiff`: toglie i brani il cui originale non c'è più (quelli senza `origin`, aggiunti a mano, restano), aggiunge i nuovi riusando prima la libreria (`sameInLibrary`: stesso `origin` o stesso titolo senza "(Remastered)" ecc. e durata ±15 s; file prima di YouTube), poi cercando su YouTube (`yt.findMatch`, 101 unità; `bestMatch`: durata ±15 s, parole del titolo, niente live/cover, esclusi i video `blocked` = limitati per età o bloccati in Italia da `contentDetails`, che yt-dlp non scarica; i non trovati vanno in `missingKeys` e non si ricercano). Menu brano «Cambia video YouTube» (brani YouTube e file nati da YouTube/copia; `changeVideo`: foglio con brano di riferimento e durata Spotify (`refTrack`, `refMs`), ricerca modificabile `yt.searchFor` (ordinata con `scoreMatch`, non scaricabili in fondo), video attuale segnato, differenza di durata (rossa oltre 10 s), «Guarda» apre YouTube, link incollato; sostituisce quel video/file in tutte le playlist tenendo nomi, copertina e `origin`; un file torna «da scaricare»). Nella copia i brani da scaricare con durata diversa da Spotify oltre 10 s mostrano «⚠︎ durata diversa» (`refMs` = durata Spotify, messa da `withMeta`), e ordina come l'originale (`orderLike`). I brani della copia prendono titolo, artista e copertina del brano Spotify d'origine (`withMeta`); `store.replaceTrack` tiene copertina e artista del brano sostituito se il nuovo non li ha; `enrichFiles` (avvio, dopo importazione e aggiornamento) sistema i file senza copertina dall'origine o da un brano con lo stesso titolo; per i file nati da YouTube copertina da `i.ytimg.com/vi/<id>/mqdefault.jpg` (id = `ytId` o `[id]` nel nome del file) e artista (canale) da `yt.videos`, 1 unità ogni 50 (`fillArtists`). Vecchie copie senza `origin`: `adoptOrigins` (anche all'avvio, in `enrichFiles`) per parole di titolo/artista e durata, o per ordine + durata entro 3 s; il titolo YouTube resta in `ytTitle` (usato anche per riconoscere i file senza `[id]`). La copia è 1:1 con Spotify: nomi, artisti e copertine di Spotify. Più chiavi API YouTube (Impostazioni → YouTube: una riga per chiave con «attiva»/«esaurita oggi», Aggiungi / elimina; salvate unite da virgola in `settings.youtubeApiKey`; «Prova le chiavi» = `yt.testKeys` con `videos` da 1 unità; motivo dell'errore per chiave in `hp.yt.keystatus` (`why`: quota, API non abilitata, chiave non valida, restrizioni); una chiave guasta non blocca le altre), a quota finita si passa alla successiva (`hp.yt.spent` per giorno di quota, `yt.apiKeys`/`yt.spent`). Barra in cima a ogni playlist con brani da scaricare o file mancanti: "Scarica tutti (N)" (un solo invio ad a-Shell) e "Importa file (N mancanti)" (`importDownloaded`: scelta multipla, ogni file si collega per `[id]` nel nome, o per titolo se manca, a quel brano YouTube in tutte le playlist; file già importati riconosciuti con `findSameFile`; i file mancanti si ricreano con lo stesso id (`findMissingFile`: nome del file, codice video `[id]`/`ytId`, poi titolo Spotify o `ytTitle`; se il nome non basta `missingByDuration`: durata del file entro 1,5 s da quella salvata + parole del titolo); a fine importazione, se ci sono file non riconosciuti, foglio con l'elenco dei nomi; file che non corrispondono a niente ignorati; riepilogo finale).
- Playlist: `pinned` (fissate in alto); "Rimuovi da Duetto" non tocca Spotify.
- `web/js/player.js`: coordinatore della coda; segue con il polling i brani che Spotify suona da solo (`run`). Logica testata in `tests/player.test.js` con adapter finti.
- Funzioni pure in `web/js/util.js`. Test: `npm test` (node --test). Avvio locale: `npm start` → http://127.0.0.1:8000
- **A ogni rilascio** incrementare `VERSION` in `web/js/version.js` e `CACHE` in `web/sw.js` (stesso numero): fa scattare l'aggiornamento: a ogni avvio e ritorno `checkForUpdate` legge `js/version.js` senza cache; se più nuova ricarica (`forceUpdate`, svuota le cache) quando non suona, una sola volta per versione, altrimenti avviso "Aggiorna"; pulsante "Aggiorna ora" in Impostazioni e il numero si vede in Impostazioni e nella diagnostica. Se si aggiungono file JS, aggiornare anche l'elenco `SHELL`.
- Dispositivo Spotify: quello salvato ha sempre la precedenza (mai prendere il dispositivo attivo di un altro sullo stesso account); il dispositivo attivo si usa solo se non ce n'è uno salvato.
